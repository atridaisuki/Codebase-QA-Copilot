## 第一部分：数学与算法基础（你说的"底层没理解"的部分）

### 1.1 向量与相似度计算

你用了 embedding + cosine similarity，但没手算过。

**练习：**
- 手算余弦相似度：向量 [1,2] 和 [2,4]，公式 = dot(a,b) / (|a| * |b|)

- 写一个 `cosine_similarity(a, b)` 函数，不用任何库，只用 Python 列表
- 理解：为什么方向相同的向量余弦值 = 1？为什么 embedding 用余弦而不是欧氏距离？

- 3Blue1Brown "Essence of Linear Algebra" 系列（B站有中文字幕）
- 只需要看前 4 集：向量、线性组合、矩阵变换、点积

### 1.2 RRF（Reciprocal Rank Fusion）

你项目里用了但没细看公式。

**练习：**
- 公式：`score(d) = weight / (k + rank)`，k=60
- 手算：向量搜索返回 [A, B, C]（rank 1,2,3），BM25 返回 [B, D, A]（rank 1,2,3）
  - A 的融合分 = 1/(60+1) + 1/(60+3) = ?
  - B 的融合分 = 1/(60+2) + 1/(60+1) = ?
- 思考：k 越大，排名差异的影响越小，为什么？（提示：当 k=1000 时，rank 1 和 rank 3 的分数差多少？）

### 1.3 BM25 算法

你用了 rank-bm25 库但可能不知道它在算什么。

**核心概念：**
- TF（词频）：这个词在这篇文档里出现了几次
- IDF（逆文档频率）：这个词在所有文档里有多罕见
- BM25 就是 TF-IDF 的改进版，加了文档长度归一化

**练习：**
- 3 篇文档：["猫 喜欢 鱼", "狗 喜欢 骨头", "猫 喜欢 骨头"]
- 查询 "猫"，手算每篇文档的 BM25 分数（简化版，忽略参数调优）
- 理解：为什么 "的" 这种高频词 IDF 很低？

### 1.4 Sigmoid 函数与分数归一化

你的 reranker 用了 sigmoid 归一化。

**练习：**
- sigmoid(x) = 1 / (1 + e^(-x))
- 手算 sigmoid(0) = ?  sigmoid(2) = ?  sigmoid(-2) = ?
- 画出曲线（用 matplotlib 或纸笔）
- 理解：为什么用 sigmoid 做归一化？（把任意范围的分数压到 0-1）

**你需要理解的：**

**练习：**

- 试试用词相同但语义不同的句子（"苹果很好吃" vs "苹果股价上涨"），看相似度

### 2.2 向量数据库的工作原理

- HNSW 算法的直觉理解（不需要看论文，理解"跳表"的类比就行）
- Chroma 底层用的就是 HNSW

**练习：**
- 用纯 Python 实现一个暴力搜索的"向量数据库"（遍历所有向量，算余弦，排序）
- 对比 Chroma 的搜索结果和你的暴力搜索结果，应该一致（或非常接近）

## 第三部分：Agent 基础（从"会写 ReAct 循环"到"理解 Agent 设计模式"）

### 3.1 你已经会的

### 3.2 你需要补的

**a) Planning 模式**
- 当前项目：LLM 每一步只看当前状态决定下一步（reactive）
- 进阶：LLM 先生成完整计划，再按计划执行（proactive）
- 练习：写一个 prompt，让 Claude 把"对比 React 和 Vue"拆成 3-5 个子问题，输出 JSON

**b) 多 Agent 协作**
- 当前项目：单个 agent + 多个 tool
- 进阶：多个 agent 各有专长，互相协作
- 概念理解：
  - Supervisor 模式：一个"经理" agent 分配任务给"员工" agent
  - Peer 模式：agent 之间平等协作，互相传递信息
- 不需要现在实现，理解概念即可，新项目里会用到

**c) 状态管理与记忆**
- 当前项目：LRU 内存存储对话历史
- 进阶：
  - 短期记忆：当前对话上下文（你已经有了）
  - 工作记忆：当前任务的中间状态（比如"已经搜索了 3 个子问题，还剩 2 个"）
  - 长期记忆：跨会话的知识积累（向量数据库存储）
- 练习：想想你的 deep research agent 需要哪种记忆？每种怎么实现？

**d) 工具设计原则**
- 当前项目的问题：3 个工具功能重叠，LLM 不知道什么时候该用哪个
- 好的工具设计：
  - 每个工具职责单一、边界清晰
  - 工具之间有互补性（搜索 vs 计算 vs 写入）
  - 工具描述要让 LLM 能准确判断何时使用
- 练习：为 deep research agent 设计 4-5 个工具，写出每个工具的 name、description、parameters
